# V5.1 Historical Feature Integrity

The 2017-2025 walk-forward windows require every model feature to have real point-in-time observations in those periods.

The current public FII/DII feed used by the repository does not provide sufficient historical coverage for the training horizon used by V5.1. The previous run demonstrated this by producing all-missing `fii_net_z`, `dii_net_z`, `fii_fut_long_short`, `pcr`, and `flow_sentiment` columns, which sklearn then skipped during imputation.

Until a validated historical source covers the required windows, these five features are explicitly excluded from the V5.1 model rather than being imputed as if historical information existed.

Re-enabling any disabled flow feature requires:

1. Verified historical coverage from the earliest required training date through the latest test date.
2. Point-in-time availability with no future-filled values.
3. A feature-level observed-value coverage report for every walk-forward training window.
4. A fresh independent-inspector pass before the expensive backtest.

This policy prevents a green compute run from being mistaken for a valid research experiment when critical historical features are silently unavailable.
